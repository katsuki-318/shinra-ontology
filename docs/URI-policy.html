01原則
URI は変えない。URI が変わるとリンクが死ぬ。

オントロジーの価値はリンクの安定性に依存する。個人ドメイン（例: miwa.dev）は廃止リスクがあるため、永続 URI サービス w3id.org を使用する。w3id.org への PR を提出し、GitHub Pages へのリダイレクトを設定する。

04クラス・プロパティ・インスタンスの URI 設計

クラス — 名前空間直後に PascalCase の英語名（単数形）

https://w3id.org/shinra/ont/MaterialEntity https://w3id.org/shinra/ont/InformationContentEntity https://w3id.org/shinra/ont/ConceptualEntity

プロパティ — 名前空間直後に lowerCamelCase の英語動詞句

https://w3id.org/shinra/ont/participatesIn https://w3id.org/shinra/ont/hasPart https://w3id.org/shinra/ont/aboutness

インスタンス — 意味のある slug（英語小文字・ハイフン区切り）+ UUID 短縮（6文字）

https://w3id.org/shinra/data/tokyo-station-a3f4c9 https://w3id.org/shinra/data/natsume-soseki-b2e7d1

slug は人間可読性のため。UUID 部分がリネームへの耐性を担保する。

05バージョニング
種別変更の例
MAJORBFO ブリッジクラスの再設計、上位階層の根本変更
MINOR新ドメインモジュール（shinra-bio.ttl 等）の追加

OWL バージョン宣言の書き方:

<https://w3id.org/shinra/ont/> a owl:Ontology ; owl:versionIRI <https://w3id.org/shinra/ont/2026-05-12/> ; owl:versionInfo "0.0.1" ; dcterms:created "2026-05-12"^^xsd:date ; dcterms:title "神羅万象オントロジー"@ja , "Shinra Ontology"@en ; dcterms:license <https://creativecommons.org/licenses/by/4.0/> .
06外部語彙との整合
語彙再利用方法import
BFO 2020クラス・プロパティを継承owl:imports で完全 import
OWL-Time時間表現の型完全 import（Phase 2）
QUDT量・単位の型完全 import（Phase 2）
PROV-O来歴の記述完全 import（Phase 2）
SKOS概念マッピング述語語彙のみ参照（import しない）
FOAF人物プロパティ語彙のみ参照（import しない）
Dublin Coreメタデータ語彙のみ参照

Wikidata マッピングのルール: インスタンスは owl:sameAs、クラスは skos:exactMatch / skos:closeMatch。クラスへの owl:equivalentClass は推論爆発の原因になるため禁止。

07凍結ルール（変更禁止事項）
  • 1ベース URI（https://w3id.org/shinra/）は変更しない
  • 2クラス・プロパティ名の ASCII slug は変更しない。skos:notation の連番 ID でリネームを追跡する
  • 3名前空間の分離方式（/ont/ と /data/ の区別）は変更しない

クラス名を変えたい場合は、旧クラスに owl:deprecated true を追加して残し、新クラスに owl:sameAs 参照を追記する。旧クラスは削除しない。
